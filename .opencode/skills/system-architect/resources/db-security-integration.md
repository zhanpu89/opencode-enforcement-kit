## 数据库设计规范

> 语言特化的 ORM 选型详见 `resources/overlays.md`。

### RBAC：始终使用三表模型
多角色系统使用 `t_user`（仅身份） + `t_role`（角色定义） + `t_user_role`（多对多关联）。禁止在 `t_user` 内嵌 `role` 字段。

### JSON 字段：谨慎使用
仅当数据结构真正可变、无需过滤/排序/聚合、始终整体读写时使用。**禁止**在 WHERE 子句、唯一性约束、需单独查询的场景使用。

### 敏感字段：静态加密
PII 字段（手机号、身份证号、邮箱）：主列 AES-256-GCM 加密 + 加盐哈希列（`HASH(value + server_secret)`）用于查找，加 UNIQUE 索引。

### 通用命名规范
| 规范项 | 规则 |
|--------|------|
| 表前缀 | `t_` |
| 软删除 | `deleted`（0=正常，1=已删除） |
| 时间戳 | `created_at`、`updated_at` |
| 操作人 | `created_by`、`updated_by` |
| 状态字段 | 整型，注释中列出所有枚举值 |

### 非功能性要点
- **索引**：为 WHERE/JOIN/ORDER BY 高频字段建索引，避免低基数字段单独索引
- **分区**：日志/时序表按时间范围分区；业务表 > 5000 万行评估分表
- **连接池**：明确 max_connections，与数据库对齐
- **慢查询**：阈值 ≥ 500ms，说明监控方案

## 安全设计检查清单

> 语言特化实现详见 `resources/overlays.md`。

### 认证与 Token 策略
| 检查项 | 说明 |
|--------|------|
| **Token 机制** | 单 Token vs 双 Token（Access + Refresh）。用户端优先双 Token + 无感刷新 |
| **Token 存储** | httpOnly Cookie / localStorage / 内存，选型权衡 |
| **Token 吊销** | 黑名单 / Token 轮换 |
| **会话管理** | 并发会话处理，是否限制最大设备数 |

### 敏感数据加密
| 检查项 | 说明 |
|--------|------|
| **密码** | bcrypt cost ≥ 12 或 Argon2。禁止 MD5/SHA1 |
| **PII 字段** | AES-256-GCM 加密 + 哈希列 |
| **第三方 OAuth Token** | 单向哈希，禁止明文 |
| **传输安全** | HTTPS/TLS 1.2+（优先 1.3） |
| **文件访问** | 预签名 URL TTL ≤ 1 小时 |

### API 安全
| 检查项 | 说明 |
|--------|------|
| **限流** | 按 IP 和用户分别限流，敏感接口指定阈值 |
| **防重放** | 敏感写操作需 `X-Timestamp` + `X-Nonce`，偏差 > 5 分钟或 Nonce 已用过则拒绝 |
| **输入校验** | 使用框架校验机制，禁止 SQL 拼接 |
| **RBAC 执行** | 每个端点声明所需角色，明确数据隔离规则 |

### 审计与合规
| 检查项 | 说明 |
|--------|------|
| **审计日志** | 所有写操作含操作人、动作、资源、IP、请求体（脱敏）、结果、耗时。保留 ≥ 3 年 |
| **脱敏** | 手机号、姓名、身份证号在日志和 API 响应中脱敏 |
| **合规** | 注明适用法规（个人信息保护法、GDPR 等） |

## 特殊集成设计规范

> 在模块设计之后添加专属章节（第 10 节）。

### 区块链集成（FISCO BCOS / Hyperledger Fabric）
- **上链策略**：链上 vs 链下（推荐：数据存 MySQL，SHA-256 哈希上链）
- **智能合约**：完整 Solidity/链码源码含注释
- **哈希计算**：参与字段、顺序、分隔符
- **异步上链**：业务操作 → MQ → 链消费者 → 上链 → 回写 tx hash
- **节点规划**：数量、角色（共识/观察者）、机构分配
- **验证流程**：重算哈希 → 调用 verifyHash()

### 支付集成
- 支付服务商选型及理由、支付流程时序图（含回调/Webhook）
- 幂等性策略（防止重复扣款）、退款流程、签名验证、HTTPS 回调校验

### 文件存储集成（OSS / MinIO）
- Bucket 结构与命名规范、直传 vs 服务端转发决策
- 预签名 URL 生成与 TTL 策略、文件哈希计算（完整性验证/存证）、CDN 配置
