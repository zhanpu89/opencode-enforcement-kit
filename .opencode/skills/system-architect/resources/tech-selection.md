# 技术选型参考

> Step 4 技术选型时加载。包含六大评估维度和完整技术目录。

## 六大评估维度

| 维度 | 关键问题 |
|------|---------|
| **成熟度与稳定性** | 生产就绪？持续维护？大规模案例？ |
| **性能** | 满足吞吐量/并发？延迟可接受？ |
| **可扩展性** | 水平扩展？数据分区？无状态友好？ |
| **运维复杂度** | 部署简单？可观测性成熟？学习曲线？ |
| **成本** | 许可证费用？基础设施？隐性成本？ |
| **团队技术储备** | 实战经验？学习曲线？文档/社区？ |

## 决策原则

1. **开源优先** — 避免厂商锁定　2. **务实优于完美** — 成熟技术，避免过度设计
3. **可落地的设计** — 团队能运维的选择　4. **可扩展性与性能** — 为增长而设计
5. **安全内建** — 安全记录良好、补丁活跃

## 技术目录

### 后端框架
| 框架 | 语言 | 优势 | 劣势 | 最适合 |
|------|------|------|------|--------|
| Spring Boot | Java | 生态完善、企业级、事务支持强 | 重、启动慢 | 企业级应用 |
| FastAPI | Python | 高性能异步、自动生成 OpenAPI | 生态较 Spring 弱 | 微服务、AI 服务 |
| Gin | Go | 极高性能、编译快 | 生态较 Spring 弱 | 网关、代理服务 |

### 数据库
| 数据库 | 类型 | 优势 | 劣势 | 最适合 |
|--------|------|------|------|--------|
| PostgreSQL | 关系型 | 功能完整、稳定、可扩展 | 水平扩展复杂 | 通用场景、复杂查询 |
| MySQL | 关系型 | 简单、快速、广泛采用 | 高级特性较少 | Web 应用、互联网级读取 |
| Redis | 键值型 | 极快、数据结构丰富 | 受内存限制 | 缓存、会话、实时数据 |
| MongoDB | 文档型 | Schema 灵活、水平扩展简单 | 事务支持弱 | 非结构化数据 |
| Elasticsearch | 搜索/分析 | 全文搜索、强大聚合 | 复杂度高、内存占用大 | 日志分析、全文搜索 |

### 消息队列
| 队列 | 优势 | 劣势 | 最适合 |
|------|------|------|--------|
| RabbitMQ | 功能完整、可靠、支持事务 | 复杂度较高 | 可靠消息传递、复杂工作流 |
| Kafka | 超高吞吐、持久化、流处理 | 学习曲线陡 | 日志收集、流处理 |
| Redis Queue | 简单、快速 | 功能有限、可靠性较低 | 简单任务队列 |

### 前端框架（Web）
| 框架 | 优势 | 劣势 | 最适合 |
|------|------|------|--------|
| Vue3 | 渐进式、学习曲线平缓、国内生态好 | 大型项目架构约束弱 | 中后台系统、国内团队 |
| React | 生态最大、灵活性高、Hooks 成熟 | 学习曲线较陡 | 大型应用、国际化团队 |

**推荐组合：** Vue3+TS+Vite+Element Plus+Pinia+Vue Router 4+Axios / React 18+TS+Vite+Ant Design+Zustand+React Router 6+Axios

### 小程序框架
| 框架 | 优势 | 劣势 | 最适合 |
|------|------|------|--------|
| 微信原生 | 性能最好、官方支持 | 仅限微信 | 性能敏感、仅需微信 |
| Taro | 多端支持、React 语法 | 多端适配有坑 | 多端发布、React 团队 |
| uni-app | 多端支持最广、Vue 语法 | 性能略低于原生 | 多端发布、Vue 团队 |

### 基础设施
| 类别 | 推荐选型 | 备注 |
|------|---------|------|
| 容器化 | Docker + docker-compose | 单机/开发环境 |
| 容器编排 | Kubernetes | 生产级微服务 |
| 监控 | Prometheus + Grafana | 指标监控 |
| 日志 | ELK Stack | 集中式日志 |
| CI/CD | GitLab CI / GitHub Actions | 按代码托管平台 |
| 文件存储 | MinIO（自托管）/ OSS（云） | 按部署环境 |

**组合示例：** 小型→FastAPI+PG+Redis+Docker Compose / 中型→Spring Boot+PG+Redis+RabbitMQ+K8s+ELK / 大型→Spring Boot+PG+Redis+Kafka+K8s+商业APM

## SAD 层协作边界

> 与 task-decomposer 协作，避免重复劳动。

| 章节 | system-architect（SAD 层） | task-decomposer（详设层） |
|------|--------------------------|-------------------------|
| **数据库设计** | 核心表名+关键字段+ER关系+索引策略 | 完整 DDL |
| **API 设计** | 端点列表+HTTP方法+功能描述+认证方案 | 完整 OpenAPI 3.0 Schema |
| **模块设计** | 模块划分+职责+依赖关系 | 伪代码逻辑+算法细节+测试用例 |
| **前端路由/页面** | 页面清单+路由路径+权限要求（F2） | 交互规则+API 调用映射+组件逻辑 |
| **小程序页面** | tabBar 结构+分包策略+微信能力集成 | 生命周期钩子+缓存策略+错误处理 |
