# 访谈与提问框架

> 用于指导结构化需求访谈。在 Step 1-2 澄清阶段加载。

---

## 1. 5W1H 框架（核心提问）
### Who（用户）
- "这个功能是为谁设计的？谁会用？谁会受益？"
- "是所有用户都能用，还是特定角色（如 VIP、管理员）？"
- "用户现在的替代方案是什么？"
### What（内容 / 问题）
- "用户真正想解决的核心问题是什么？是表面需求还是深层需求？"
- "请描述一下这个功能成功运行后的样子？"
- "如果不做这个功能，最坏的结果是什么？"
### Why（目的）⭐ 最重要
- "为什么我们一定要现在做这个？它解决了哪个业务指标？"
- "这个需求背后的原始驱动力是什么？"
### When（时机）
- "用户希望在什么时间点用到这个功能？（特定节日还是日常通用？）"
- "这个需求的时效性如何？"
### Where（地点 / 场景）
- "用户在什么环境下使用？（嘈杂工厂还是安静办公室？WiFi 还是 5G？）"
- "是在 PC 端用，还是在手机端？"
### How（方式）
- "用户希望怎么完成这个操作？（三步完成还是一键完成？）"
- "目前业务的流程是怎样的？新流程会改变现有习惯吗？"

## 2. 边界与异常框架（反向提问）

- **逆向思维**：「如果用户操作到一半退出了，数据怎么处理？」
- **极限思维**：「如果瞬间有 1 万人同时点击这个按钮，系统扛得住吗？」
- **无数据情况**：「如果接口返回失败，或者网络超时，页面给用户看什么？」
- **边界情况**：「如果用户输入了表情符号、1000 个字、负数，怎么办？」
- **权限边界**：「如果普通用户误操作了管理员才能做的事，系统怎么拦截？」

## 3. KANO 模型（优先级评估）

| 需求类型 | 判断问题 | 处理策略 |
|---------|---------|---------|
| **基本型**（底线） | "如果没有这个功能，你是不是会很不满意？" | 必须做，不做就失败 |
| **期望型**（投入产出比最高） | "有这个功能，你是不是会更满意？没有就不满意？" | 优先做，ROI 最高 |
| **兴奋型**（加分项） | "有这个功能会让你惊喜吗？没有也不会觉得有问题？" | 有余力再做 |

## 4. 需求冲突处理框架 ⭐

### 4.1 冲突类型识别
| 冲突类型 | 典型表现 | 示例 |
|---------|---------|------|
| **目标冲突** | 不同角色对成功的定义不同 | 产品要增长 vs 运营要控成本 |
| **优先级冲突** | 对功能重要性判断不一致 | 技术认为性能优化是 M，产品认为是 C |
| **技术可行性冲突** | 业务需求与技术实现存在矛盾 | 要求实时同步但网络延迟无法保证 |
### 4.2 冲突处理步骤

**Step 1：识别并命名冲突** — 识别 [A方]/[需求A] 与 [B方]/[需求B] 的互斥点。
**Step 2：记录冲突（在 PRD 草稿中标注）**
```
⚠️ 待决策项 [CONFLICT-001]
冲突描述：[简要描述冲突内容]
涉及方：[A方] vs [B方]
冲突点：[具体的互斥点]
备选方案：
  - 方案 A：[描述] → 优点：[...] 缺点：[...]
  - 方案 B：[描述] → 优点：[...] 缺点：[...]
决策人：[需要谁来拍板]
截止日期：[需要在什么时间前决策]
```
**Step 3：提供决策建议** — 从业务目标角度建议方案，请决策人确认。
**Step 4：阻断生成，等待决策** — 在决策确认前暂缓生成相关章节，避免返工。
### 4.3 冲突记录模板（在 PRD 文档中使用）

```markdown
### 待决策项汇总

| 编号 | 冲突描述 | 涉及方 | 备选方案 | 决策人 | 状态 |
|------|---------|-------|---------|-------|------|
| CONFLICT-001 | [描述] | [A] vs [B] | 方案A / 方案B | [姓名] | 🔴 待决策 |
| CONFLICT-002 | [描述] | [A] vs [B] | 方案A / 方案B | [姓名] | 🟢 已决策：方案A |
```

## 5. 范围确认清单

- [ ] **端类型已锁定**：所有端已逐一列举，文件清单已确认
- [ ] 核心业务问题已清晰定义
- [ ] 目标用户及其痛点已识别
- [ ] 成功指标具体可衡量
- [ ] 范围边界明确（包含/不包含）
- [ ] 关键功能需求已详细描述，每个 M/S 级功能有初步 AC 方向
- [ ] **需求冲突已识别并记录**（无冲突则标注"无冲突"）

## 6. 端类型专属访谈问题

### 6.1 Web 前端专属问题

- **页面范围**：「核心页面有哪些？请列举主要的页面或功能模块。」
- **访问终端**：「用户主要在 PC 浏览器还是手机浏览器上使用？」
- **权限边界**：「是否有多种角色？不同角色看到的页面或功能是否不同？」
### 6.2 微信小程序专属问题
- **登录方式**：「用户如何登录？微信一键登录还是账号密码？」
- **支付需求**：「是否需要在小程序内完成支付？主要支付场景是什么？」
- **分享需求**：「是否需要支持分享到好友或朋友圈？」
### 6.3 多端并存专属问题
- **功能差异**：「各端功能完全一致，还是有差异化？」
- **数据一致性**：「各端操作的数据是否需要实时同步？」
### 6.4 纯后端专属问题
- **调用方**：「这个后端服务的调用方是谁？」
- **一致性要求**：「哪些业务操作不允许数据不一致？哪些可接受短暂延迟？」
- **安全与权限**：「哪些功能仅限内部访问？哪些对外开放？」
